# Loom UI 页面原型说明 v0.1

## 1. 文档信息

- 项目名称：Loom
- 文档版本：v0.1
- 文档类型：UI 页面原型说明 / Wireframe Spec
- 目标阶段：MVP / 第一阶段落地
- 关联文档：
  - `loom-architecture-v0.1.md`
  - `loom-api-and-interaction-v0.1.md`
  - `loom-mvp-breakdown-v0.1.md`

## 2. 文档目标

本文档用于把 Loom 的页面设计从“功能描述”进一步落地为页面级原型说明，帮助后续前端开发、组件拆解和交互实现。

本文档重点描述：

- 页面结构
- 信息层级
- 关键组件
- 核心交互
- 状态变化

当前文档以低保真线框说明为主，不追求视觉设计稿，而强调产品结构和实现优先级。

## 3. 设计原则

Loom 的 UI 必须服务于“低噪音、高信息密度、快速判断优先级”的目标，因此遵循以下原则：

- 时间线优先
- 信息密度优先于装饰性
- 聚合优先于平铺
- 重要性与热度要一眼可见
- 中英对照要自然，不喧宾夺主
- 来源展开要快，不打断主流阅读

## 4. 页面总览

Loom MVP 建议包含 3 个核心页面：

- 实时时间线页面
- 来源配置页面
- 系统状态页面

辅助区域包括：

- 顶部导航
- 筛选栏
- 详情抽屉或侧边面板

## 5. 全局布局建议

## 5.1 页面结构

推荐使用三段式布局：

```text
┌──────────────────────────────────────────────┐
│ Top Navigation                              │
├──────────────────────────────────────────────┤
│ Filter Bar / Context Toolbar                │
├──────────────────────────────────────────────┤
│ Main Content Area                           │
│  ├─ Timeline List / Config Table / Status   │
│  └─ Side Panel / Detail Drawer              │
└──────────────────────────────────────────────┘
```

## 5.2 顶部导航

建议包含：

- Loom Logo / 项目名
- 时间线
- 来源配置
- 系统状态

可选：

- 最后同步时间
- 网络状态小圆点
- LM Studio 状态小圆点

## 6. 页面一：实时时间线

## 6.1 页面目标

这是 Loom 的主页面，用于按时间线展示经过聚合的信息卡片，并支持快速判断：

- 这件事是什么
- 是否重要
- 是否正在发酵
- 谁在报道

## 6.2 页面区域划分

```text
┌────────────────────────────────────────────────────────────┐
│ Top Navigation                                             │
├────────────────────────────────────────────────────────────┤
│ 分类筛选 | 来源筛选 | 排序 | 高重要性开关 | 搜索           │
├────────────────────────────────────────────────────────────┤
│ Timeline List                                │ Detail Panel │
│                                              │              │
│ [Cluster Card]                               │ 展开详情      │
│ [Cluster Card]                               │ 来源列表      │
│ [Cluster Card]                               │ 原文链接      │
│                                              │              │
└────────────────────────────────────────────────────────────┘
```

## 6.3 顶部筛选栏

建议组件如下：

- 分类下拉
- 来源下拉
- 排序切换
- 仅高重要性开关
- 搜索框
- 手动刷新按钮

### 排序选项

- 最新
- 重要性
- 热度

### 分类选项

- 全部
- 时政
- AI
- 科技
- 数字货币
- 金融
- 公司
- 宏观
- 安全
- 产品发布
- 其他

## 6.4 时间线卡片结构

主时间线默认展示 Cluster 卡片，而不是单条 Message。

### 卡片字段建议

- 主标题
- 中文摘要
- 英文原文切换入口
- 分类标签
- 自定义 tags
- 来源数
- 消息数
- 重要性分数
- 热度分数
- 最新时间
- 原始链接
- 展开全部来源按钮

### 低保真结构示意

```text
┌─────────────────────────────────────────────────────────┐
│ [AI] [模型发布]                           重要性 91 热度 76 │
│ GPT-X 发布                                                 │
│ 多家来源报道 OpenAI 发布新模型 GPT-X。                    │
│                                                           │
│ 来源 4 · 消息 5 · 2 分钟前                                │
│ [查看原文] [展开全部来源] [查看英文]                      │
└─────────────────────────────────────────────────────────┘
```

## 6.5 中英对照交互

对于英文原始消息或以英文消息为代表的聚合卡片：

- 默认展示中文标题和中文摘要
- 提供“查看英文”切换
- 点击后可展开英文标题与英文摘要

### 建议形式

不建议默认双栏平铺中英文，那会让时间线过于拥挤。  
推荐使用：

- 中文默认显示
- 英文折叠展开

## 6.6 展开全部来源交互

点击“展开全部来源”后，建议在右侧详情面板或卡片下展开来源列表。

### 来源列表字段

- 来源名称
- 原始标题
- 中文标题
- 语言标记
- 发布时间
- 原始链接

### 示例

```text
来源 1：OpenAI Blog    [EN]
Introducing GPT-X
推出 GPT-X
08:00  [打开原文]

来源 2：TechCrunch    [EN]
OpenAI launches GPT-X
OpenAI 发布 GPT-X
08:03  [打开原文]
```

## 6.7 卡片状态设计

### 普通状态

- 默认展示卡片内容

### 新消息高亮

- 新进来的卡片短暂高亮边框或背景

### AI 处理中

- 中文摘要或分类未完成时显示轻量状态
- 例如“AI 处理中”

### 无摘要

- 仅展示标题、来源数和链接

## 7. 页面二：来源配置

## 7.1 页面目标

让用户能在 UI 中管理 API 与 Feed 来源，而无需修改代码。

## 7.2 页面区域划分

```text
┌────────────────────────────────────────────────────┐
│ Top Navigation                                     │
├────────────────────────────────────────────────────┤
│ [新增来源] [筛选：全部/API/Feed] [搜索]            │
├────────────────────────────────────────────────────┤
│ Source Table                                       │
│ ┌────────────────────────────────────────────────┐ │
│ │ 名称 | 类型 | 频率 | 分类 | 状态 | 操作       │ │
│ └────────────────────────────────────────────────┘ │
└────────────────────────────────────────────────────┘
```

## 7.3 来源列表表格字段

- 名称
- 类型
- 地址
- 轮询频率
- 默认分类
- 启用状态
- 健康状态
- 最近成功时间
- 操作按钮

### 操作按钮建议

- 编辑
- 测试
- 启停
- 删除

## 7.4 新增/编辑来源表单

建议使用抽屉或弹窗，字段包括：

- 来源名称
- 来源类型
- endpoint
- method
- headers
- auth
- 轮询频率
- 默认分类
- 是否启用

### 表单交互建议

- 来源类型切换时动态显示字段
- Feed 来源隐藏 method
- headers 与 auth 采用结构化输入或 JSON 文本输入

## 7.5 测试连接反馈

点击“测试”后，应在 UI 中展示：

- 测试是否成功
- 预览抓取条数
- 失败原因

不建议只给一个笼统的失败提示。

## 8. 页面三：系统状态

## 8.1 页面目标

让用户快速判断 Loom 是否正常工作。

## 8.2 页面区域划分

```text
┌────────────────────────────────────────────────────┐
│ Top Navigation                                     │
├────────────────────────────────────────────────────┤
│ Status Cards                                       │
│ [网络状态] [LM Studio] [最近同步] [最近清理]       │
├────────────────────────────────────────────────────┤
│ Sources Health List                                │
├────────────────────────────────────────────────────┤
│ Stats Section                                      │
│ 7天消息量 / 聚合组数 / 启用来源数                  │
└────────────────────────────────────────────────────┘
```

## 8.3 状态卡片建议

### 网络状态

- online / offline

### LM Studio 状态

- healthy / failed / disconnected

### 最近同步

- 最近一次调度执行时间

### 最近清理

- 最近一次 TTL 清理时间

## 8.4 来源健康列表

建议字段：

- 来源名
- 当前状态
- 最近成功时间
- 最近错误时间
- 最近错误摘要

## 10. 状态与反馈设计

## 10.1 Loading

每个页面应具备基础 loading 状态：

- 时间线 skeleton
- 来源表格 loading
- 状态页 loading

## 10.2 Empty State

### 时间线空状态

- 当前暂无消息
- 可提示检查来源配置或网络状态

### 来源空状态

- 尚未添加来源
- 提供“立即添加来源”按钮

## 10.3 Error State

### 时间线错误

- 加载失败
- 提供重试按钮

### 来源测试错误

- 显示详细错误原因

## 10.4 实时更新提示

新消息到达时建议：

- 顶部轻提示
- 或列表顶部插入高亮卡片

避免突然跳动影响阅读。

## 11. 交互细节建议

## 11.1 时间线滚动行为

- 默认顶部展示最新消息
- 用户正在向下阅读时，新消息到达不应强制打断
- 可显示“有 3 条新消息”提示，点击后滚回顶部

## 11.2 展开来源行为

推荐优先使用右侧详情面板，而不是直接把卡片无限撑高。

原因：

- 保持时间线整体节奏稳定
- 适合多来源列表浏览
- 便于后续加入更多详情信息

## 11.3 分数字段展示

建议使用简洁 badge：

- 重要性：深色强调
- 热度：暖色强调

不必做复杂图表，数字和等级就足够。

## 12. 响应式建议

尽管 Loom 是本地桌面优先应用，仍建议支持基础响应式。

### 宽屏

- 时间线 + 右侧详情双栏

### 中等宽度

- 时间线单栏
- 详情改为抽屉

### 窄屏

- 仅保证基本可用，不作为 MVP 重点

## 13. 页面实现优先级

## 13.1 P0

- 顶部导航
- 时间线基础页面
- 来源配置页
- 系统状态页基础版
- Cluster 卡片
- 来源展开面板

## 13.2 P1

- 更细的 loading / empty / error 状态
- 新消息提示
- 英文切换体验优化

## 13.3 P2

- 更精细的视觉分层
- 键盘快捷操作
- 个性化布局偏好

## 14. 页面级验收标准

## 14.1 时间线页

- 能展示聚合卡片
- 能筛选和排序
- 能展开来源
- 能查看原始链接
- 英文信息可查看中英对照

## 14.2 来源配置页

- 能新增、编辑、启停、删除来源
- 能测试连接
- 能看到来源健康状态

## 14.3 系统状态页

- 能看到网络状态
- 能看到 LM Studio 状态
- 能看到启用来源数和近 7 天统计

## 15. 结论

Loom 的 UI 第一版不应追求复杂视觉，而应聚焦于三个核心体验：

- 主时间线足够清晰
- 聚合与展开来源足够顺手
- 来源配置与系统状态足够透明

按照本文档推进，前端已经可以从页面壳、核心组件和交互流程三个层面开始实施。
