# Loom 开发任务拆分清单 v0.1

## 1. 文档信息

- 项目名称：Loom
- 文档版本：v0.1
- 文档类型：开发任务拆分清单 / Backlog
- 目标阶段：MVP / 第一阶段落地
- 关联文档：
  - `loom-mvp-breakdown-v0.1.md`
  - `loom-api-and-interaction-v0.1.md`
  - `loom-database-schema-v0.1.md`
  - `loom-ai-workflow-v0.1.md`

## 2. 文档目标

本文档将 Loom 的架构与模块设计进一步拆解为可以直接执行的开发任务清单，便于后续按 issue、milestone 或迭代计划推进。

本文档重点回答：

- 第一版到底要做哪些具体任务
- 哪些任务优先级最高
- 哪些任务之间存在依赖
- 每个任务完成的验收口径是什么

## 3. 使用方式

建议把本文档作为 MVP 阶段的 backlog 基线，后续可以按以下方式使用：

- 每个一级任务对应一个 milestone
- 每个二级任务对应一个 issue
- 按 P0 / P1 / P2 安排执行顺序
- 每完成一个模块即更新文档状态

## 4. 优先级定义

### P0

必须优先完成，决定 Loom 是否具备基本可用性。

### P1

增强产品价值，但不应阻塞基础可用版本形成。

### P2

稳定性、体验或后续扩展项，可在主链路完成后补齐。

## 5. Milestone 总览

建议将 Loom MVP 分为 6 个里程碑：

- M1：本地应用骨架与工程初始化
- M2：来源配置与采集调度
- M3：消息标准化与时间线
- M4：AI 增强能力
- M5：聚合、评分与展开来源
- M6：生命周期、状态页与打磨

## 6. Backlog 详细清单

## 6.1 M1：本地应用骨架与工程初始化

### 目标

完成前后端基础工程，让 Loom 能在本地启动。

### 任务清单

#### P0-001 初始化 monorepo 工程

- 建立 `apps/web`、`apps/server`、`packages/shared`
- 配置 workspace
- 配置基础脚本

验收标准：

- 项目可安装依赖
- 前后端可分别启动

#### P0-002 初始化前端应用壳

- 建立 React + TypeScript + Vite 工程
- 配置基础路由
- 建立应用布局

验收标准：

- 本地页面可打开
- 至少有首页占位

#### P0-003 初始化后端服务壳

- 建立 Node + TypeScript + Fastify 服务
- 建立健康检查接口
- 建立基础日志能力

验收标准：

- 本地服务可启动
- 健康检查接口返回成功

#### P0-004 初始化共享类型包

- 建立共享类型目录
- 放入基础枚举与 DTO

验收标准：

- web 和 server 可共享基础类型

#### P0-005 初始化数据库连接与迁移机制

- 接入 SQLite
- 初始化迁移框架
- 建立第一版建库脚本

验收标准：

- 本地可生成数据库文件
- 可执行初始迁移

## 6.2 M2：来源配置与采集调度

### 目标

让用户可以在页面配置来源，并让系统定时拉取数据。

### 任务清单

- 实现基本 CRUD

验收标准：

- 能写入、读取、更新、删除来源

- `GET /api/sources`
- `POST /api/sources`
- `PUT /api/sources/:sourceId`
- `DELETE /api/sources/:sourceId`
- `PATCH /api/sources/:sourceId/status`

验收标准：

- API 可完整管理来源

#### P0-008 实现来源配置页面

- 来源列表
- 新建表单
- 编辑表单
- 启停操作

验收标准：

- 页面上可完整管理来源

#### P0-009 实现来源测试能力

- 后端测试连接接口
- 前端按钮与结果展示

验收标准：

- 可对单个来源执行连接测试

#### P0-010 实现本地调度器

- 按来源频率执行任务
- 支持启停来源

验收标准：

- 启用来源后会自动定时执行抓取

#### P0-011 实现 API Fetcher

验收标准：

- 能抓到结构化 API 数据

#### P0-012 实现 Feed Fetcher

- 支持 RSS/Atom 拉取

验收标准：

- 能抓到 feed 消息并转成统一中间结构

#### P1-013 实现来源健康状态记录

- 成功/失败状态更新
- 最近错误记录

验收标准：

### 任务清单

- 建立消息表

验收标准：

#### P0-018 实现主时间线页面基础版本

- 链接跳转

验收标准：

- 新消息可在页面上看到

#### P0-019 实现 WebSocket 基础推送

- 建立前后端连接
- 新消息触发前端刷新

验收标准：

- 新消息入库后前端自动更新

#### P1-020 实现分类筛选与搜索

- 分类筛选
- 关键词搜索

验收标准：

- 页面可以按分类或关键词过滤

#### P0-028 实现 `clusters` 表与 repository

验收标准：

- 聚合组可入库和查询

验收标准：

验收标准：

## 7. 依赖关系摘要

```text
工程初始化
→ 来源配置
→ 调度抓取
→ 标准化入库
→ 时间线展示
→ AI 增强
→ 聚合与评分
→ 清理与状态页
```

## 7.2 阻塞性任务

以下任务属于强阻塞项：

- P0-001 到 P0-005
- P0-006 到 P0-012
- P0-014 到 P0-019

这些完成前，后续高级能力无法形成有效验证闭环。

## 8. 推荐执行顺序

若要最短路径看到成果，建议按以下顺序执行：

1. P0-001 ~ P0-005
2. P0-006 ~ P0-012
3. P0-014 ~ P0-019
4. P0-021 ~ P0-024
5. P0-028 ~ P0-034
6. P0-038 ~ P0-041
7. P1 项目
8. P2 项目

## 9. 完成定义

当以下条件全部满足时，可视为 Loom MVP 开发完成：

- 能在本地启动并打开页面
- 能配置多个 API / Feed 来源
- 能自动拉取消息
- 主页面能实时展示信息
- 英文消息有中英对照
- 多源重复消息会聚合
- 可展开查看全部来源
- 可看到重要性与热度
- 数据仅保留 7 天
- 可在状态页观察系统健康情况

## 10. 结论

本文档将 Loom 的设计拆解为 44 个任务项，并按优先级与里程碑组织完成。它适合作为后续开发迭代的执行底稿，也适合直接转化为 issue 清单或项目看板。
